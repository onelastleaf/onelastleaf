# __OLL_PLUGIN_NAME__

This is a Kotlin onelastleaf plugin generated by `oll plugin new`. The sample
`echo` action returns its arguments in order, giving you a working path through
the SDK before you add your own actions.

## Requirements

- JDK 21
- Gradle
- oll

## Build and test

```sh
gradle --no-daemon classes
gradle --no-daemon test
```

Reuse `.gradle/` and `build/` for incremental compilation. Both directories
are already ignored by Git. To inspect the runnable layout manually, run
`gradle --no-daemon installDist` and look under `build/install/`.

## Local source development

Install from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, test and run `oll plugin update __OLL_PLUGIN_NAME__`. oll builds
inside this workspace, allowing Gradle to reuse its incremental outputs. The
update publishes a new generation but does not replace a running process, so
restart the plugin to load the new code.

## Local release development

Stage the application distribution together with the exact `oll.toml` that
should launch it:

```sh
gradle --no-daemon -PinstallDir=build/oll-release/package installDist
cp oll.toml build/oll-release/package/oll.toml
tar -czf build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C build/oll-release/package .
```

Create `oll-release.json` in the project root:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Choose your machine's canonical target, then exercise that package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

For normal development, edit, test, update the source installation, restart,
and call the action. Before publishing, repeat the check in release mode so a
missing JAR, launcher, or manifest cannot hide behind workspace state. oll must
launch the distribution because it owns the private endpoint and lifecycle.

## Publish a release

Build and upload an archive for each target you support. Replace local `path`
entries with remote `url` entries, then add exact `size_bytes` and SHA-256
`sha256` values. Commit both manifests, tag the release, and check the same
route users will follow:

Linux packages use `tar.gz`; Darwin packages use `zip`. Keep each filename,
target, and `archive` value aligned.

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
