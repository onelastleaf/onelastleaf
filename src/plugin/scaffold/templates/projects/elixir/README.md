# __OLL_PLUGIN_NAME__

This is an Elixir onelastleaf plugin generated by `oll plugin new`. Its sample
`echo` action returns its arguments in order, so you can start with a working
SDK call.

## Requirements

- Elixir 1.17 or newer with Mix
- oll

## Build and test

```sh
mix deps.get
mix compile
mix escript.build
mix test
```

Keep `deps/` and `_build/` for dependency and incremental compiler state.
The generated escript is written to `__OLL_PLUGIN_NAME__`; all three paths are
already ignored by Git.

## Local source development

Install from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, test and run `oll plugin update __OLL_PLUGIN_NAME__`. The source
recipe works in this directory, allowing Mix to reuse `deps/` and `_build/`.
Updating publishes a new generation without replacing a running process;
restart the plugin to load the new escript.

## Local release development

Stage the escript beside the exact runtime manifest and archive that directory:

```sh
mix deps.get
mix escript.build
mkdir -p _build/oll-release/package
install -m 755 __OLL_PLUGIN_NAME__ \
  _build/oll-release/package/__OLL_PLUGIN_NAME__
cp oll.toml _build/oll-release/package/oll.toml
tar -czf _build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C _build/oll-release/package .
```

Create `oll-release.json` in the project root:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "_build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Choose the canonical target for the Elixir/Erlang runtime you tested, then
exercise the package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

Use source mode while editing: test, update, restart, and call. Before
publishing, use local release mode to catch a missing escript, incompatible
runtime, or stale manifest. Do not launch the escript directly; oll provides
the private plugin endpoint and manages the process.

## Publish a release

Build and upload an archive for each supported target. Replace every local
`path` with a remote `url`, add the exact `size_bytes` and SHA-256 `sha256`,
commit both manifests and `mix.lock`, then tag the release. Verify the public
install:

Linux packages use `tar.gz`; Darwin packages use `zip`. Keep each filename,
target, and `archive` value aligned.

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
