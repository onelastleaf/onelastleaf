# __OLL_PLUGIN_NAME__

This is a Rust onelastleaf plugin generated by `oll plugin new`. The sample
`echo` action returns its arguments in order, leaving you with a working action
to extend.

## Requirements

- Rust and Cargo
- oll

## Build and test

```sh
cargo build --release
cargo test
```

Keep `target/` as the incremental build directory; Cargo reuses dependencies
and object files there, and Git already ignores it. Commit the generated
`Cargo.lock`: oll's source recipe deliberately installs with `--locked`.

## Local source development

Install directly from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, run the tests and `oll plugin update __OLL_PLUGIN_NAME__`. The
source recipe builds from this workspace and can reuse `target/`. Updating
publishes a new generation but does not replace the running process, so restart
the plugin when you are ready to try the new binary.

## Local release development

Stage the release binary with the exact `oll.toml` that should launch it. This
example creates a GNU/Linux x86-64 package:

```sh
cargo build --release
mkdir -p target/oll-release/package/bin
install -m 755 target/release/__OLL_PLUGIN_NAME__ \
  target/oll-release/package/bin/__OLL_PLUGIN_NAME__
cp oll.toml target/oll-release/package/oll.toml
tar -czf target/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C target/oll-release/package .
```

Create `oll-release.json` in the project root:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "target/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Choose the canonical target matching your machine, then exercise the package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

Use source mode for quick edits: test, update, restart, and call the action. Use
local release mode before publishing to catch missing binaries, wrong paths,
and a stale manifest. Do not run the binary by hand; oll supplies its private
endpoint and owns the process lifecycle.

## Publish a release

Build one archive for every supported target. Upload the archives, replace each
local `path` with a remote `url`, and add the exact `size_bytes` and SHA-256
`sha256`. Commit the manifests and `Cargo.lock`, tag the release, and verify the
same route your users will follow:

Linux packages use `tar.gz`; Darwin packages use `zip`. Keep each filename,
target, and `archive` value aligned.

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
