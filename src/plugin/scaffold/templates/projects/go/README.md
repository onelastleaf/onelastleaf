# __OLL_PLUGIN_NAME__

This is a Go onelastleaf plugin generated by `oll plugin new`. Its sample
`echo` action returns its arguments in order and is ready to call.

## Requirements

- Go 1.24 or newer
- oll

## Build and test

```sh
go build ./cmd/plugin
go test ./...
```

The generated `go.mod` and `go.sum` pin the SDK's module graph. After changing
dependencies, run `go mod tidy` and commit both files.

Go's shared build and module caches are the recommended incremental build
state. Use `build/` only for project-local release staging; keeping it between
builds makes repeated package checks predictable without mixing binaries into
the source tree.

## Local source development

Install directly from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, run the tests and `oll plugin update __OLL_PLUGIN_NAME__`. The
source recipe compiles this workspace, so Go can reuse its ordinary caches.
Updating publishes a new generation without disturbing a running process; use
`oll plugin restart __OLL_PLUGIN_NAME__` to switch the process to that build.

## Local release development

Stage a platform binary beside the exact runtime manifest, then archive that
directory. This example targets GNU/Linux on x86-64:

```sh
mkdir -p build/oll-release/package
go build -o build/oll-release/package/__OLL_PLUGIN_NAME__ ./cmd/plugin
cp oll.toml build/oll-release/package/oll.toml
tar -czf build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C build/oll-release/package .
```

Create `oll-release.json` in the project root:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Choose the canonical target for your machine, then install and run the package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

Use source mode while changing code: test, update, restart, and call the action.
Use release mode before publishing to prove that the standalone archive—not an
unintended file from your workspace—is sufficient. oll must start the binary
because it provides the private plugin endpoint and manages the process.

## Publish a release

Cross-compile or natively build one archive per supported target. Upload the
archives, replace each `path` with a remote `url`, and add the exact
`size_bytes` and SHA-256 `sha256`. Commit both manifests, tag the release, and
verify the public install path:

Linux packages use `tar.gz`; Darwin packages use `zip`. Keep each filename,
target, and `archive` value aligned.

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
