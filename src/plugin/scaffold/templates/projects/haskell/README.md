# __OLL_PLUGIN_NAME__

This is a Haskell onelastleaf plugin generated by `oll plugin new`. The sample
`echo` action returns its arguments in order and gives you a known-good action
to extend.

## Requirements

- GHC 9.6 or newer
- cabal-install
- oll

## Build and test

```sh
cabal build exe:__OLL_PLUGIN_NAME__
cabal test
```

`cabal list-bin exe:__OLL_PLUGIN_NAME__` prints the executable path. Keep
`dist-newstyle/` as the project-local incremental build directory; Cabal also
reuses its global package store. The directory is already ignored by Git.

## Local source development

Install from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

This template uses `install` checkout, so oll copies the workspace into a
private candidate before running Cabal. After an edit, test and run `oll plugin
update __OLL_PLUGIN_NAME__`; Cabal can still reuse its global store. The update
does not replace a running process, so restart the plugin to load the result.

## Local release development

Install the executable into a clean package root, add the exact runtime
manifest, and archive the result:

```sh
mkdir -p dist-newstyle/oll-release/package
cabal install exe:__OLL_PLUGIN_NAME__ --install-method=copy \
  --installdir=dist-newstyle/oll-release/package \
  --overwrite-policy=always
cp oll.toml dist-newstyle/oll-release/package/oll.toml
tar -czf \
  dist-newstyle/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C dist-newstyle/oll-release/package .
```

Create `oll-release.json` beside `oll.toml`:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "dist-newstyle/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Choose the canonical target matching your GHC build, then test the archive:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

For normal work, edit, test, update the source installation, restart, and call.
Before publishing, exercise the local release archive so a missing executable,
runtime library, or bad manifest cannot hide behind the build tree. Let oll
launch the binary because it owns the private endpoint and lifecycle.

## Publish a release

Build and upload an archive for each target you support. Replace local `path`
entries with remote `url` entries and add exact `size_bytes` and SHA-256
`sha256` values. Commit both manifests, tag the release, and verify the public
path:

Linux packages use `tar.gz`; Darwin packages use `zip`. Keep each filename,
target, and `archive` value aligned.

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
