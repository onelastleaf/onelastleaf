# __OLL_PLUGIN_NAME__

This is a Clojure onelastleaf plugin generated by `oll plugin new`. The sample
`echo` action returns its arguments in order and gives you a known-good action
while you shape the real plugin.

## Requirements

- JDK 21
- Gradle
- oll

## Build and test

```sh
gradle --no-daemon classes
gradle --no-daemon test
```

Reuse `.gradle/` and `build/`; they hold Gradle's dependency and incremental
build state and are already ignored by Git. Run `gradle --no-daemon
installDist` to inspect a runnable distribution under `build/install/`.

## Local source development

Install from the current workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, test and run `oll plugin update __OLL_PLUGIN_NAME__`. oll's
source recipe uses this workspace, so Gradle can keep its caches warm. An update
publishes a new generation without replacing the running process; restart the
plugin when you want that process to load the new build.

## Local release development

Stage the application distribution with the exact `oll.toml` used to launch
it:

```sh
gradle --no-daemon -PinstallDir=build/oll-release/package installDist
cp oll.toml build/oll-release/package/oll.toml
tar -czf build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C build/oll-release/package .
```

Create `oll-release.json` in the project root:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Choose the canonical target matching this machine, then install the package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

For ordinary work, edit, test, update the source installation, restart, and
call. Before publishing, use local release mode to catch missing runtime JARs,
launch scripts, or a stale manifest. Let oll launch the distribution because it
owns the private endpoint and process lifecycle.

## Publish a release

Build and upload one archive for every supported target. Replace each local
`path` with a remote `url`, then add exact `size_bytes` and SHA-256 `sha256`
values. Commit both manifests, tag the release, and verify the public install:

Linux packages use `tar.gz`; Darwin packages use `zip`. Keep each filename,
target, and `archive` value aligned.

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
