# __OLL_PLUGIN_NAME__

This is a JavaScript/Node.js onelastleaf plugin generated by `oll plugin new`.
The sample `echo` action returns its arguments in order and is ready to call.

## Requirements

- Node.js 20 or newer with pnpm
- oll

## Build and test

```sh
pnpm install
pnpm test
```

JavaScript runs directly, so there is no compilation step. `node_modules/` and
pnpm's content-addressed store are the recommended incremental dependency
state. Use `build/` for release staging; both project directories are ignored
by Git.

## Local source development

Install from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, test and run `oll plugin update __OLL_PLUGIN_NAME__`. This
template uses `install` checkout, so oll copies the workspace into a private
generation and runs pnpm there. Updating publishes that copy without replacing a
running process; restart the plugin to load it.

## Local release development

Stage only the runtime source and production dependencies, together with the
exact `oll.toml` that should launch them:

```sh
mkdir -p build/oll-release/package
cp -R src build/oll-release/package/src
cp package.json pnpm-lock.yaml pnpm-workspace.yaml \
  build/oll-release/package/
pnpm --dir build/oll-release/package \
  --config.package-import-method=copy \
  --config.enable-global-virtual-store=false \
  install --prod --frozen-lockfile
cp oll.toml build/oll-release/package/oll.toml
tar -czf build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C build/oll-release/package .
```

Create `oll-release.json` in the project root:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Choose the canonical target matching your Node.js runtime, then test the
package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

The two project settings keep `.pnpm` self-contained while preserving pnpm's
archive-internal links. The explicit command flags override a developer's
global configuration for the packaging step. On Darwin, create the required
zip with a tool and flag that retain symbolic links, such as
`zip -yr <package>.zip .`.

## Development loop

Use source mode for the usual edit, test, update, restart, and call cycle. Use
local release mode before publishing to make sure the package really contains
its production dependencies and runtime files. Do not run `src/index.js`
directly; oll supplies the private endpoint and manages the process.

## Publish a release

Build an archive for each supported target and upload it. Replace every local
`path` with a remote `url`, add the exact `size_bytes` and SHA-256 `sha256`,
commit both manifests and `pnpm-lock.yaml`, then tag the release. Verify the
public route:

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
