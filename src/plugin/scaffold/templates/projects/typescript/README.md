# __OLL_PLUGIN_NAME__

This is a TypeScript/Node.js onelastleaf plugin generated by `oll plugin new`.
Its sample `echo` action returns its arguments in order, giving you a working
SDK call before you add your own actions.

## Requirements

- Node.js 20 or newer with pnpm
- oll

## Build and test

```sh
pnpm install
pnpm run build
pnpm test
```

Keep `node_modules/` and `dist/` for the incremental development loop, and use
`build/` for release staging. All three directories are ignored by Git.

## Local source development

Install from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, test and run `oll plugin update __OLL_PLUGIN_NAME__`. This
template uses `install` checkout: oll copies the workspace, runs the package's
`prepare` build with pnpm in a private generation, and publishes that generation. It
does not replace a running process, so restart the plugin to load the new
JavaScript.

## Local release development

Compile once, then stage the JavaScript output and production dependencies with
the exact runtime manifest:

```sh
pnpm run build
mkdir -p build/oll-release/package
cp -R dist build/oll-release/package/dist
cp package.json pnpm-lock.yaml pnpm-workspace.yaml \
  build/oll-release/package/
pnpm --dir build/oll-release/package \
  --config.package-import-method=copy \
  --config.enable-global-virtual-store=false \
  install --prod --ignore-scripts --frozen-lockfile
cp oll.toml build/oll-release/package/oll.toml
tar -czf build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C build/oll-release/package .
```

`--ignore-scripts` is intentional: `dist/` is already built, and the staging
directory does not contain the TypeScript source needed by `prepare`.

Create `oll-release.json` beside `oll.toml`:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Choose the canonical target matching your Node.js runtime, then test the
package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

The two project settings keep `.pnpm` self-contained while retaining pnpm's
archive-internal links. The explicit command flags override a developer's
global configuration for the packaging step. On Darwin, create the required
zip with a tool and flag that preserve symbolic links, such as
`zip -yr <package>.zip .`.

## Development loop

Use source mode for normal edits: test, update, restart, and call. Use local
release mode before publishing to catch stale `dist/` output, omitted
dependencies, or a bad manifest. Do not run `dist/index.js` directly; oll
supplies the plugin endpoint and owns the process lifecycle.

## Publish a release

Upload an archive for each target you support. Replace local `path` entries
with remote `url` entries and add exact `size_bytes` and SHA-256 `sha256`
values. Commit both manifests and `pnpm-lock.yaml`, tag the release, and verify
the public install:

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
