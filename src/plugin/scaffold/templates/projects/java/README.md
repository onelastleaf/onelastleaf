# __OLL_PLUGIN_NAME__

This is a Java onelastleaf plugin generated by `oll plugin new`. Its sample
`echo` action is ready to call and returns its arguments in order.

## Requirements

- JDK 21
- Gradle
- oll

## Build and test

```sh
gradle --no-daemon classes
gradle --no-daemon test
```

Keep `.gradle/` and `build/` between runs. They are the recommended
incremental build directories and are already ignored by Git. Run `gradle
--no-daemon installDist` when you want a runnable distribution under
`build/install/`.

## Local source development

Install from the current workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, test and run `oll plugin update __OLL_PLUGIN_NAME__`. The source
recipe works in this directory, so Gradle can reuse its incremental state. An
update publishes the new generation without replacing a running process; use
`oll plugin restart __OLL_PLUGIN_NAME__` when you are ready to try it.

## Local release development

Create a self-contained application distribution and put the exact runtime
manifest at its root:

```sh
gradle --no-daemon -PinstallDir=build/oll-release/package installDist
cp oll.toml build/oll-release/package/oll.toml
tar -czf build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C build/oll-release/package .
```

Create `oll-release.json` beside `oll.toml`:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Select the canonical target matching your machine, then test the package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

Use source mode for the fast loop: edit, test, update, restart, and call. Before
publishing, use local release mode to catch a missing JAR, launch script, or
manifest. Let oll launch the distribution because it supplies the private
plugin endpoint and manages the process.

## Publish a release

Build a distribution for every supported target and upload each archive. In
`oll-release.json`, replace each local `path` with its remote `url` and add
the exact `size_bytes` and SHA-256 `sha256`. Commit both manifests, tag the
release, and verify the public install path:

Linux packages use `tar.gz`; Darwin packages use `zip`. Keep each filename,
target, and `archive` value aligned.

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
