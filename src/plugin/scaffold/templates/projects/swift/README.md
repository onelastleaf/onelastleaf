# __OLL_PLUGIN_NAME__

This is a Swift onelastleaf plugin generated by `oll plugin new`. Its sample
`echo` action returns its arguments in order and is ready for a first call.

## Requirements

- Swift 6.2 or newer
- macOS 15 or newer when building for macOS
- oll

## Build and test

```sh
swift build --configuration release
swift test
```

SwiftPM normally uses `.build/` for incremental work. oll deliberately uses
`build/` as its scratch directory, so keep both between development builds;
they are already ignored by Git.

## Local source development

Install from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, test and run `oll plugin update __OLL_PLUGIN_NAME__`. The source
recipe builds in this workspace with `build/` as its scratch path, preserving
incremental compilation. An update publishes a new generation but leaves a
running process alone; restart the plugin to switch to it.

## Local release development

Build the release executable, stage it beside the exact runtime manifest, and
create the zip required for Darwin:

```sh
swift build --configuration release --scratch-path build
mkdir -p build/oll-release/package
install -m 755 build/release/__OLL_PLUGIN_NAME__ \
  build/oll-release/package/__OLL_PLUGIN_NAME__
cp oll.toml build/oll-release/package/oll.toml
(cd build/oll-release/package && \
  zip -r ../../__OLL_PLUGIN_NAME__-dev-aarch64-apple-darwin.zip .)
```

Create `oll-release.json` in the project root:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "aarch64-apple-darwin",
        "path": "build/__OLL_PLUGIN_NAME__-dev-aarch64-apple-darwin.zip",
        "archive": "zip"
      }]
    }
  }
}
```

Use `x86_64-apple-darwin` instead on an Intel Mac, then test the package:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

Use source mode for normal edits: test, update, restart, and call. Before
publishing, install the local release archive to catch a missing executable,
wrong architecture, or stale manifest. Do not launch the executable directly;
oll provides the private endpoint and manages the process.

## Publish a release

Build and upload a zip for each supported Darwin target. Replace each local
`path` with a remote `url`, add exact `size_bytes` and SHA-256 `sha256`,
commit both manifests, and tag the release. Verify the public path:

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
