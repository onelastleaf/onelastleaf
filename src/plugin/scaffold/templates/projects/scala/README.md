# __OLL_PLUGIN_NAME__

This is a Scala onelastleaf plugin generated by `oll plugin new`. Its sample
`echo` action returns its arguments in order, so the initial project already
has a complete request path.

## Requirements

- JDK 21
- Gradle
- oll

## Build and test

```sh
gradle --no-daemon classes
gradle --no-daemon test
```

Keep `.gradle/` and `build/` between runs so Gradle and the Scala compiler can
reuse their incremental state. Both are ignored by Git. A manual `gradle
--no-daemon installDist` writes the runnable distribution under
`build/install/`.

## Local source development

Install from this workspace, then start or recycle the plugin:

```sh
oll plugin install . --source
oll plugin restart __OLL_PLUGIN_NAME__
oll plugin call __OLL_PLUGIN_NAME__ echo -- one two
```

After an edit, test and run `oll plugin update __OLL_PLUGIN_NAME__`. The source
recipe works in this directory and reuses the normal Gradle caches. Updating
publishes a new generation but does not replace a running process; restart the
plugin to put that generation into service.

## Local release development

Build the complete application distribution and include the exact runtime
manifest at its root:

```sh
gradle --no-daemon -PinstallDir=build/oll-release/package installDist
cp oll.toml build/oll-release/package/oll.toml
tar -czf build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz \
  -C build/oll-release/package .
```

Create `oll-release.json` beside `oll.toml`:

```json
{
  "format_version": 1,
  "plugin_id": "__OLL_PLUGIN_ID__",
  "default_release": "dev",
  "releases": {
    "dev": {
      "packages": [{
        "target": "x86_64-unknown-linux-gnu",
        "path": "build/__OLL_PLUGIN_NAME__-dev-x86_64-unknown-linux-gnu.tar.gz",
        "archive": "tar.gz"
      }]
    }
  }
}
```

Use the canonical target for the current machine, then test the archive:

```sh
oll plugin install . --release dev
oll plugin restart __OLL_PLUGIN_NAME__
```

## Development loop

Use source mode for quick iteration: edit, test, update, restart, and call. Use
local release mode before publishing to prove the package includes the launcher,
all required JARs, and the right manifest. Do not launch it directly; oll
provides the private endpoint and manages the process.

## Publish a release

Produce and upload an archive for every supported target. Replace each local
`path` with a remote `url`, add the exact `size_bytes` and SHA-256 `sha256`,
commit both manifests, and tag the release. Finally, test the public route:

Linux packages use `tar.gz`; Darwin packages use `zip`. Keep each filename,
target, and `archive` value aligned.

```sh
oll plugin install <git-remote> --release <release-id>
oll plugin restart __OLL_PLUGIN_NAME__
```
